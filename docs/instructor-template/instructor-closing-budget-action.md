# 收尾段教案 — 正式導入決策、預算、行動清單（15 分鐘）

> 原 4 模組版的 Module ④（45m 工程/預算）壓縮成 15 分鐘收尾。
> 完整預算單與升降級信號保留在這給學員帶回去（也放投影片附錄）。

---

## WHAT
把三階段收斂成一個**決策框架**：公司今天該停在哪一段？預算大概多少？什麼時候該升級/降級？
給每位學員一份能**帶回去 brief 老闆/CFO** 的東西。

## WHY
PM/主管回到公司，老闆會問兩件事：「**要花多少錢**」「**要不要找工程師自建**」。
這段就是給他們現成的答案框架，避免「上完課很興奮、回公司講不清楚」。

## 四套預算範本（範本，學員回去要重算）

| 方案 | 對應做法 | 月費（台幣） | 一次性 | 適合 |
|------|----------|--------------|--------|------|
| **A · MVP 試水溫** | ChatGPT 做法 + 工程小幫手 | ~1,400 | 30,000 | 驗證需求、小型、單語系 |
| **B · 正式上線** | Dify cloud | ~11,000 | 80,000 | 中型、多通路、多語系 |
| **C · 規模化** | 自架 Dify + 自建 vector DB | ~135,000 | 250,000 | 大型 B2C、資料留自家雲 |
| **D · 企業級** | 完全自建 / on-prem | ~320,000 | 1,100,000 | 金融/醫療/政府、嚴格合規 |

> 對 CFO 的話術範例：
> 「方案 B 第一年 = 80k + 11k×12 = **21.2 萬**；省下 1 個客服人力（~6 萬/月）→ **4 個月回本**。」
> 「方案 D 第一年 ≈ **494 萬**；但若是合規驅動，那不是投資、是**保險**。」

## 升降級信號（避免過度工程）

**該升級**
- ChatGPT 做法 → Dify：文件 >50 頁、要串通路、多人協作改 prompt、客戶抱怨找不到資料
- Dify → 工程：答錯率穩定 >15% 查不出原因、領域術語 embedding 抓不到、合規 audit 不過、月對話 >10 萬

**該降級（別過度工程）**
- 工程 → Dify：團隊只有 1 個工程師、改 prompt 要過三層審
- Dify → ChatGPT：對話量 <100/月、只內部用、外部整合需求消失

> **圖譜（Stage 3）的升級信號**：客服問題大量是「同供應商/同政策/同方案」這種**關聯/多跳**，
> 純向量答錯率高且調 chunk/Top-K 都救不了 → 評估加圖譜。否則別上。

## 帶走的「1 週 / 1 個月 / 3 個月」清單

```
1 週內：
  □ 用 ChatGPT 做法做一個「公司內部 FAQ bot」(自己用，先別給客戶)
  □ 列出公司所有客服文件清單、估算總頁數
  □ 觀察一週客服信件，分類意圖（查詢 / 投訴 / 退費 / 閒聊）

1 個月內：
  □ 用 worksheet 自評 + 對齊老闆預算，決定走哪種做法
  □ 若走 Dify：註冊、做 PoC（一份知識庫、一個通路）
  □ 找 1-2 個內部客服當 alpha tester、收 50 通對話 log

3 個月內：
  □ 小規模上線（一個通路、一個語系）
  □ 設 3 個監控指標：解決率、轉接率、滿意度
  □ retrospect 答錯案例：retrieval 錯？prompt 錯？知識庫錯？還是這是「關係問題」該上圖譜？
  □ ROI 證明後規劃下一階段（擴通路 / 擴語系 / 評估圖譜）
```

## 最後一句（送學員出門）
> 「今天你帶走的不是一個 bot，是一張**地圖**：知道自己公司現在站在哪、下一步往哪、什麼時候別走太遠。」
