## WHAT
在 Stage 2 的 Dify 客服 app 上，**外掛一個「圖譜知識庫」**（LightRAG / GraphRAG），
和原本的「內建向量知識庫」並用。用一組對照查詢，現場展示：
**同一個問題，純向量答不全，加上圖譜就答得齊。**

## WHY（這段的靈魂，務必講透）

> 用一句話定錨：**「向量 RAG 是『找像的句子』，圖譜 RAG 是『走通的關係』。」**

- **向量檢索**＝把文字變成向量，找「語意最相似」的片段。擅長：找定義、找相似敘述。
- **盲區**：客服知識裡有大量**關聯式 / 多跳**問題 —
  「跟這支豆**同供應商**的還有哪些？」「跟這個方案**同政策又同產線**的有哪些？」
  「這個供應商斷貨會**連帶影響**哪些商品和促銷組合？」
  這些答案分散在多個片段，向量各自抓 chunk、**接不起來**。
- **圖譜檢索**＝先把資料抽成「實體 + 關係」（商品─供應商─產線─政策─組合），
  查詢時**沿著邊走**，一次撈齊相關實體。這正好補向量的盲區。
- **結論金句**：「進階導入時，圖譜不是炫技，是**補向量盲區**。但它成本更高（要抽圖譜、要維護），
  所以是**該用才用**，不是一開始就上。」

## 架構（投影一張圖）
```
Dify 客服 app
 ├── 內建知識庫（向量 RAG）         ← Stage 2 已建（語意相似）
 └── 外部知識庫（External Knowledge API）
        └── POST /retrieval ──► LightRAG（向量 + 知識圖譜，mix 模式）
```
重點講：Dify 用一個標準契約 `POST /retrieval`（帶 query + top_k），
**任何**會回 `records[]` 的 GraphRAG 服務都能插上來 — 這就是「外掛」。

## HOW-TO（講師示範流程，60 分鐘）

| 時間 | 步驟 | 講師動作 |
|------|------|----------|
| 10m | 為何要圖譜 | 講上面的 WHY，用「同供應商還有哪些」這種問題讓學員直覺認同 |
| 5m | 架構導覽 | 投影架構圖，說明 External Knowledge `POST /retrieval` 契約 |
| 10m | 起服務 demo | 展示 `ingest.py` 把 `coffee-catalog-relationships.md` 灌成圖譜；adapter `/health` OK |
| 20m | **對照查詢主秀** | 依 `sample-queries.md` 跑 Q1→Q5，每題「純向量 vs 加圖譜」並排對照 |
| 15m | 何時該用圖譜 + Q&A | 講「公司有大量關係/多跳問題才值得上圖譜」的判斷準則；想自架的人指到選讀附錄；收 Q&A |

### 對照查詢主秀腳本（最關鍵 20 分鐘）
> 完整題目與預期答案見 `sample-queries.md`。demo 時的節奏：

1. **Q1 暖身**（同產品屬性）：兩邊都答得出 → 建立「簡單題沒差」的基準。
2. **Q2 同供應商**（1 跳）：純向量常漏；圖譜回出「西達摩」。第一個「哇」點。
3. **Q3 同產線且同政策**（2 條件 join）★主秀：純向量幾乎答不出；圖譜回「氮氣冷萃」。
4. **Q4 斷貨影響**（供應商→商品→組合，連鎖）★商業感最強：圖譜回出受影響的商品 + 促銷組合 B2。
5. **Q5 組合溯源**（組合→商品→產區）：收尾，展示反向多跳。

每題講法固定：**先問純向量（Stage 2 的內建知識庫）→ 念出它漏了什麼 → 再問加圖譜 → 對照差異。**

### ⚠️ 彩排實證：用「檢索測試」頁對照，不要用聊天機器人（重要）

> 老師彩排在老師 Dify 實跑後的結論，照這個做才穩：

- **對照主秀請開兩個「知識庫 → Retrieval Testing（檢索測試）」分頁**：① 向量 KB `ecommerce-return-sop`、② 圖譜 KB `咖啡圖譜知識庫（GraphRAG）`。同一題並排丟，直接看「召回內容」差異。
- **為什麼不用 Agent 聊天框當主秀**：客服 app 是 **Agent** 型，會自己決定要不要檢索；實測對 Q3 直接回「**信心不足→轉真人**」，沒去查圖譜 → 主秀會翻車。檢索測試頁不經過 LLM 判斷，最可靠也最直觀。
- **★ 圖譜查詢對「問法」敏感**：務必照 `sample-queries.md` 的**原句**問。實測同樣意思但加字（例「還有哪些**咖啡**豆」）會回空、甚至 500；用原句「跟耶加雪菲同供應商的還有哪些豆？」就正確回西達摩。
- 已實測通過（命中）：Q2→西達摩、Q3→氮氣冷萃、Q4→入門淺焙組、Q5→瓜地馬拉/阿里山；向量 KB 同題未命中（Q3 實測 0 vs 1）。
- **備援截圖**：`img/stage3/`（複製範本後位於 `docs/instructor/img/stage3/`）（Q2/Q4/Q5 圖譜命中全頁截圖）；現場若圖譜服務掛掉直接投影。

> 連線前提：Dify 從容器內要能連到內網 graphrag `10.20.0.6:8000` → 需先做 SSRF proxy 放行（見 teacher checklist B3③）。學員端 VM 已由 `learner-setup.sh` 自動處理。

## ⚠️ Live demo 風險與備援（重要）

圖譜 demo 牽涉 LLM 抽取與本機服務，**現場最容易出狀況**。三層備援，依序退：

1. **首選**：課前已 `ingest.py` 灌好、adapter 跑著、`sample-queries.md` 全跑過一遍。現場只查、不重灌。
2. **備援 A（零安裝）**：改用**託管的 GraphRAG**（InfraNodus，Dify 官方有 External Knowledge 教學），
   只需一把 API key，不依賴本機。
3. **備援 B（完全離線）**：準備好 Q2–Q5 的「**向量回答**」與「**圖譜回答**」**截圖**，直接投影對照。
   即使網路全掛，對照教學效果不打折。

> **絕對不要**在課堂現場第一次跑 `ingest.py`（要呼叫 LLM、數分鐘、會出錯）。一定課前灌好。
