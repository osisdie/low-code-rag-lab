一句話：Dify＝讓「不會寫程式的人」也能把 AI 做成正式產品的開源平台

它把 model 管理、向量資料庫、RAG、prompt 版本、觀測、上線部署 這些「工程苦工」包起來，你用拖拉點選就能把一個想法變成能上線的 AI 應用。
在整個社群裡，它是最多星星的開源 LLM 應用開發平台之一——也就是「這個領域最多人用來動手做東西的那個工具」。

① 它是什麼 · 為何被創建

2023 年 3 月，由 LangGenius 開始

founded · Mar 2023 · LangGenius
創辦團隊來自前騰訊雲 DevOps（做大規模上線維運出身）。名字常被解讀為 Define + Modify——先定義、再修改，正好對應它「拖拉出一個 AI 應用、再慢慢調」的做法。
出身工程維運 → 難怪它強在「從原型到上線」

一個信念：這技術應該人人都能用

why · accessibility
「LLM 這麼強的技術，不該只有工程師會用。」
所以它把最難的那幾塊（接模型、建向量庫、管 prompt、評估、部署）都做成預設好的模組，讓非工程背景的人也能幾小時做出能用的東西。

Dify 的 App 類型 · 本課用哪個

建 App 要先選「類型」，選錯會卡關——最常見的是想裝工具卻選了沒有「工具」區的 Chatbot。

類型是什麼有工具區？什麼時候用
Chatbot
（聊天助手·基礎）		最單純的對話 App：掛知識庫做 RAG、貼 system prompt❌ 無只做「照文件回答」的客服；本課超白話/非技術版用這個
Agent會自主決定要不要用「工具」的助手（function calling）✅ 有本課完整動手版用這個——因為要裝查訂單 get_order_status
Chatflow對話式工作流：用節點（知識檢索/工具/條件/LLM）自己拼✅（節點）要精細控制流程、多步驟分支（最彈性也最複雜）
Text Generator
（文本生成）		單次生成，不是對話—寫文案、翻譯、摘要這種一次性任務
Workflow非對話的多步驟自動化編排✅（節點）批次處理、後台自動化流程
本課結論：Stage 2 完整動手版（要查訂單）→ Agent（Create from Blank → More basic app types → Agent）；只做知識庫客服的超白話版 → Chatbot。
選錯的症狀：選了 Chatbot 卻找不到「工具」區、裝不了查訂單 → 改建 Agent 即可。（課堂自架與 Dify Cloud 一律用 Agent 以保持一致。）

⑥ 伴讀 · n8n：另一個你會聽到的名字

很多人會把 Dify 和 n8n 放一起問。它們其實不搶同一個位子——一句話：Dify 是「做會答的 AI 助理」的專門店；n8n 是「把各種軟體串起來自動跑」的萬用水電工。

n8n 是什麼

n8n · since 2019 · Berlin
2019 年由 Jan Oberhauser（柏林；有趣的是他是前好萊塢 VFX 特效師，做過《黑魔女》）創立。採 fair-code 授權（可免費用/改，但不能拿去做託管轉售）。核心是 400+ 現成軟體接頭（Slack、HubSpot、PostgreSQL、Google Sheets、HTTP、甚至 JS/Python 節點）。
主角是流程與事件，AI 只是其中一個節點
兩邊都很活躍

社群活躍度：Dify vs n8n

community activity
兩個都是各自領域裡社群最大、還在拿投資的頭部專案，長期維護的風險都低。差別在「主場不同」。

GitHub 星數各來源差很大（n8n 被引用到 90K～180K 都有、Dify ~131K），會持續變動、口徑不一，別拿單一數字比高低；看「同屬頭部、社群活躍」這個量級就好。

何時 Dify、何時 n8n？
• 事情從「使用者問問題」開始、你要一個會講話會查文件的助理 → Dify（本課主線）。
• 事情從「某事件發生」開始、要自動做下一件事，AI 只是流程中一步 → n8n。
而且常常兩個一起用：Dify 當「腦」（理解＋查文件＋生成），n8n 當「手腳」（接 LINE / CRM / 資料庫）。實務常見：n8n 收到 LINE 訊息 → 呼叫 Dify API 拿答案 → n8n 回傳 LINE。
