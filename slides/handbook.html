AI 很會講話，但有兩個毛病 —— 今天就是把它們補起來

① 它不知道「你公司」的事；② 不確定時，會很有自信地亂編（業界叫「幻覺 / hallucination」）。
解法就一句話：回答前，先叫它去翻你的文件再作答——這叫 RAG（開書考）。今天你會親手做一次。

① 為什麼是現在 · 產業動態與數據

先給你「大局」：這件事不是趕流行，是多數企業已經在做、而且踩過坑的方向。

② 觀念地基 · 動手前先記一句話
閉書考 vs 開書考。AI 自己回答＝閉書考，會的就答、不會就硬掰；我們今天做的是開書考——先把你公司的文件塞給它，它照著翻、照著答，還會列出「出處」。這就是 RAG。

RAG＝開書考

Retrieval-Augmented Generation
🖐️ 回答前先去翻相關文件再作答。問「退貨原則」，它先撈出你的退貨政策那幾段，再照著答。
對會計：像沒憑證不能認列；對法律：像沒查到條文就不給意見。Stage 1、2 都在做這件事。
今天你會親手做 → Stage 2

工具 / Tool Calling

tool calling · function calling
🖐️ 讓 bot 除了「會講」，還能去做事——例如查訂單、觸發轉真人。
開書考只能答「文件裡寫的」；要查即時資料（訂單到哪了）就得給它「工具」。
示範段會看到 → Stage 2 / 3

知識圖譜

knowledge graph · GraphRAG
👀 記住「誰跟誰有關係」。回答「跟這個有關的還有哪些」這種問題，一般作法會漏。
向量像 Google 找「相似句子」，圖譜像查「族譜 / 關係網」。多數公司用不到，看懂概念即可。
進階示範 → Stage 3
Stage 1 · No-Code：用 ChatGPT，親眼看它「亂編」

🖐️ 學員動手　打開 ChatGPT，貼一段「你是一家餐廳客服」，然後問它「20 人包場多少錢、能不能幫我線上訂位付訂金」。

你會看到兩個問題：① 它很自信地編出一堆價格（每人 500~800、包場 1.5~3 萬）——這些數字我們從來沒給過；② 它根本不能真的幫你訂位、收訂金。這就是天花板：很會講，但不懂你公司、也不能做事。

Stage 1 的天花板

where ChatGPT-only stops
• 出不了 ChatGPT 視窗（不能嵌到官網 / LINE）
• 不會查資料庫（沒有工具呼叫）
• 大量文件會慢、會被截斷
• 資料送到 OpenAI 伺服器
所以我們往下走 → Dify
好消息

但「有放文件」就會準很多

ChatGPT Project / Sources
實測：ChatGPT 專案沒放檔時把營業時間答錯、還自行加料；把 FAQ 放進 Sources 後，時間答對、寵物題老實說「資料沒有、請電洽」、還附引用。重點是記得把文件放進去，別靠它猜。
同場加映：NotebookLM、Gemini Gem 也能做開書考
Stage 2 · Low-Code：用 Dify，給它公司文件就不亂編

🖐️ 學員動手 · 全場重點　兩步：先做一個「文件櫃」（知識庫），再做一個「照文件回答的機器人」（Chatbot）。全程不用寫程式。

Part A · 文件櫃（知識庫）

Knowledge Base
Knowledge → Create → 把兩份文件拖進去 → 下一頁什麼都不用改、直接存 → 等它變 Available。那些設定是工程師在調的，今天用預設就好。
Top K＝白話「一次撈回幾段最相關的」給 AI 參考。今天不用動。

Part B · 機器人（Chatbot）

Chatbot app
Studio → Create → 從空白 → 選 Chatbot（別選 Agent，那是進階）→ 貼一句指令、把文件櫃掛上去。問「退貨原則」→ 它照文件回答、還列出出處。
跟 Stage 1 亂編完全不一樣——差別就在有沒有給它文件
進階概念

它怎麼「找到」對的那幾段？

vector / embedding search
不是比對一模一樣的字，是比「意思像不像」——問「退貨」，寫成「退款 / 退回商品」的段落它也找得到。
工程上叫「向量 / embedding」。你只要記：比意思，不是比關鍵字。
新知 · 查證
2026 年多語系向量模型公開榜（MTEB）第一是 Qwen3-Embedding-8B（70.58）；BGE-M3 是production 最常見預設。經驗值：Recall@10 要 >0.80，不然是在跟檢索器打架。榜單常變、多為提交者自跑，挑「有第三方複現」的用。

Stage 3 · Advanced：向量的盲區，用知識圖譜補

👀 看懂概念即可　向量像「找相似句子」，遇到「跟 X 有關係的還有哪些」這種多跳 / 關係問題會漏；知識圖譜沿著「實體→關係」走，答得齊。

別過度工程

圖譜不是萬靈丹

audit your query distribution first
研究也指出：約 80% 企業查詢是簡單語意查詢，用快速向量搜尋最划算。圖譜有建置成本＋維護負擔，只有當「問關係」的題佔可觀比例才值得。甚至有論文發現：簡單接鄰居 > 完整 GraphRAG（單一資料集）。
查證
「先量你真實的問題分布，再決定要不要建圖」——圖譜不是炫技，是補向量的盲區；沒有那類問題就別上。

③ 工具選型 · Dify vs n8n vs Coze vs Flowise

常有人問「Dify 和 n8n 有什麼不同」。一句話：Dify 是做「會答的 AI 助理」的專門店；n8n 是把各種軟體串起來自動跑的萬用水電工。

工具主角是最擅長什麼時候選它
DifyAI（大語言模型）對話式 RAG、知識庫、附出處、開箱即用要「一個會講話、會查文件的客服」← 本課主線
n8n流程 / 資料搬運串 500+ 軟體、自動化，AI 只是其中一步要「這件事發生→自動做下一件事」的產線
CozeBot（ByteDance）大量外掛、非工程師組 bot、多通路發佈想快速拼一個多通路 bot
FlowiseLangChain 視覺畫布LangChain 風格的視覺原型工程團隊想在畫布上快速試 LangChain
LangGraph / CrewAI程式碼長時多代理、毫秒級延遲、CI 級測試前面幾個撐不住規模時，才交給工程師寫
常常是兩個一起用：Dify 當「腦」（理解＋查文件＋生成），n8n 當「手腳」（把 Dify 接到 LINE / CRM / 資料庫）。實務常見：n8n 收到 LINE 訊息 → 呼叫 Dify API 拿答案 → n8n 回傳 LINE。

問與答 · FAQ（也是課後複習題）
RAG 到底是什麼？
白話就是「AI 回答前，先去翻相關文件再作答」——開書考。不是更大的模型、也不是接 LINE 的方法。
「向量 / Embedding」檢索靠什麼找資料？
靠「意思像不像」（語意相近），不是完全比對關鍵字一模一樣。問「退貨」，寫「退款」的段落也找得到。
設定裡的「Top K」是什麼？
一次撈回幾段最相關的內容給 AI 參考。不是模型多大、也不是字數或費用上限。
「工具呼叫 / Tool Calling」讓 bot 多了什麼？
能去「做事」，例如查訂單、觸發轉真人——補的是「不會查即時資料 / 不會動作」。
課堂自架的 Dify 和官方雲端 cloud.dify.ai 一樣嗎？
是同一套原始碼，建 App 的操作幾乎一樣。差別在免費額度、資料落地，不在操作介面。所以回家可以直接用 Cloud 免費版繼續練。
哪種問題純向量常答不齊、要靠知識圖譜？
「關係 / 多跳」問題，例如「跟耶加雪菲同一個供應商的還有哪些豆？」。單點題（是什麼烘焙度、運費怎麼算）純向量就夠。
一家小店、資料很少，最快最省錢怎麼做？
直接用現成 AI 工具（如 ChatGPT）上傳文件就開始問。不必先請工程師寫整套、也不必先建很大的資料庫。適合就好，別過度工程。
